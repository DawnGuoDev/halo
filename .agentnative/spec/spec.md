# 产品 Spec: Halo 控制台文章列表「仅看未分类」快捷开关

> 本 Spec 说明在 Halo Console 文章列表新增「仅看未分类」快捷开关的目标、行为规则、边界与验收标准。
> 实现细节（查询参数命名、索引方案、API Client 生成）放到下游技术设计。

---

# 1. 背景与目标

## 1.1 背景

Halo Console 的文章列表（`ui/console-src/modules/contents/posts/PostList.vue`，路由 `/posts`）是编辑整理内容分类的主要入口。当前列表已支持关键词、发布状态、可见性、分类、标签、作者、排序和分页筛选，但缺少一种直接定位「未关联任何分类」文章的方式。编辑补充分类时需要组合筛选或逐页查找，效率较低。

需求来源：用户明确要求在文章列表筛选区域增加「仅看未分类」快捷开关，方便整理遗漏分类的文章。上游产品设计已产出 PRD、高保真原型（8 篇 Mock 文章）与集成指引。

### 现状与代码证据

- 目标页面: `ui/console-src/modules/contents/posts/PostList.vue`，路由 `/posts`。
- 现有筛选: `PostList.vue` 已实现关键词（`keyword`）、发布状态（`selectedPublishStatus`）、可见性、分类（`selectedCategory`）、标签、作者、排序和分页；筛选变化时已有 `page.value = 1` 的重置行为。
- 现有空态: `PostList.vue` 使用 `VEmpty`，当前动作包含刷新与新建。
- 勾选状态: `selectedPostNames: Ref<string[]>`，批量操作完成后清空。
- 查询现状: `PostList.vue` 的 `queryFn` 通过 `fieldSelector.push("spec.categories=<value>")` 做分类包含查询；`PostQuery.java` 支持 `categoryWithChildren`，未见既有的「分类为空」查询参数。
- 索引现状: 仓库已存在 `spec.categories` 多值索引（见 `SchemeInitializer.java`），且 `FieldSelector` 支持 `isNull` 等查询（见 `TagPostCountUpdater`、`CommentServiceImpl` 等），具备表达「分类为空」的能力基础，但具体实现方式留给技术设计。
- 设计规范: 上游原型已按 Halo 设计系统（主色 `#4CCBA0`、圆角 `4px`、36px 控件高度）实现。

## 1.2 目标

| 目标 | 衡量方式 | 目标值 / 判断标准 |
|------|----------|-------------------|
| 编辑可一键查看未分类文章 | 开关开启后列表仅显示 `spec.categories` 为空或不存在的文章 | 列表结果与 Mock/真实数据一致 |
| 支持与现有筛选组合 | 开关与关键词、发布状态可同时生效，取交集 | 组合结果符合交集规则 |
| 切换行为可预期 | 切换开关时回第一页、清空勾选、保留关键词与发布状态 | 状态变更符合 REQ-004 |
| 空结果有恢复路径 | 组合筛选无结果时沿用现有空态并提供「重置筛选」 | 点击「重置筛选」恢复默认列表 |
| 原型可评审验收 | 8 篇 Mock 文章覆盖有分类/无分类/草稿/已发布 | 上游原型已通过双环境验收 |

## 1.3 不做什么

- 不修改文章编辑器、分类管理、标签管理或回收站。
- 不新增分类自动推荐、批量分类或默认分类规则。
- 不改变现有文章列表权限模型（沿用 `system:posts:view` / `system:posts:manage`）。
- 不扩展到主题端或用户中心。
- 不在本 Spec 定案后端查询参数命名、索引方案或 API Client 生成方式（留待技术设计）。
- 不新增埋点、指标或 Dashboard。

# 2. 用户与场景

| 用户 / 角色 | 使用场景 | 当前痛点 | 期望结果 |
|-------------|----------|----------|----------|
| 内容编辑 | 定期整理遗漏分类的文章 | 需逐页或组合筛选查找未分类文章，效率低 | 一键查看全部未分类文章并精确定位 |
| 内容编辑 | 在未分类文章中按关键词或状态进一步定位 | 现有筛选无法表达「分类为空」 | 开关与关键词、发布状态组合，取交集 |
| 内容编辑 | 切换筛选后继续批量操作 | 切换后勾选残留可能误操作 | 切换时清空勾选，从第一页开始 |

# 3. 功能需求

> 约定：`未分类文章` 指 `post.spec.categories` 为空数组或不存在的文章。

## REQ-001: 筛选区新增「仅看未分类」开关

- **优先级**：P0
- **用户价值**：编辑可一键定位遗漏分类的文章，无需逐页排查。
- **需求描述**：在文章列表筛选区域新增「仅看未分类」开关，默认关闭；开关为即时切换，不需要额外确认。
- **验收标准**：
  - [ ] 文章列表筛选区域显示「仅看未分类」开关。
  - [ ] 列表初始加载时开关处于关闭状态。
  - [ ] 切换开关时立即更新列表，无需额外确认动作。
  - [ ] 开关文案为「仅看未分类」，具备可访问名称与 `aria-checked` 状态。

## REQ-002: 开启后仅显示未分类文章

- **优先级**：P0
- **用户价值**：直接聚焦待整理内容。
- **需求描述**：开启后列表仅显示未关联任何分类的文章；关闭后恢复普通列表。
- **验收标准**：
  - [ ] 开关开启时，列表仅显示 `spec.categories` 为空或不存在的文章。
  - [ ] 开关关闭时，列表按普通筛选逻辑展示，不附加未分类限制。
  - [ ] 若文章引用了已不存在的分类，仍视为「已分类」（`spec.categories` 非空）。

## REQ-003: 支持与关键词和发布状态组合筛选

- **优先级**：P0
- **用户价值**：精确定位待整理文章。
- **需求描述**：开关可与关键词搜索、发布状态筛选同时生效，筛选条件之间为交集关系。
- **验收标准**：
  - [ ] 开关开启且有关键词时，仅显示匹配关键词的未分类文章。
  - [ ] 开关开启且有发布状态时，仅显示该状态的未分类文章。
  - [ ] 开关开启、有关键词且有发布状态时，仅显示同时满足两者的未分类文章。
  - [ ] 开关与现有可见性、分类、标签、作者、排序筛选共存时不破坏既有行为（本需求不要求与「分类」下拉组合，因语义互斥）。

## REQ-004: 切换开关时重置页码并清空勾选

- **优先级**：P0
- **用户价值**：避免批量操作误用切换前的选择。
- **需求描述**：切换开关时，页码回到第一页，已勾选文章清空；关键词和发布状态保留。
- **验收标准**：
  - [ ] 切换开关时 `page` 置为 1。
  - [ ] 切换开关时 `selectedPostNames` 清空。
  - [ ] 切换开关时 `keyword` 与 `selectedPublishStatus` 保持不变。
  - [ ] 切换开关时 `checkedAll` 复位为 false。

## REQ-005: 空态沿用现有结构并提供重置筛选

- **优先级**：P1
- **用户价值**：避免停留在无效筛选状态。
- **需求描述**：组合筛选无结果时沿用现有空态结构，并提供「重置筛选」操作。
- **验收标准**：
  - [ ] 组合筛选无结果时显示现有 `VEmpty` 空态结构。
  - [ ] 当存在活动筛选（开关开启、关键词或发布状态非默认）时，空态提供「重置筛选」操作。
  - [ ] 点击「重置筛选」后：开关关闭、关键词清空、发布状态清空、页码回 1、勾选清空，列表恢复默认。
  - [ ] 无活动筛选时空态沿用现有「刷新」「新建」操作，不额外显示「重置筛选」。

## REQ-006: 原型 Mock 数据覆盖

- **优先级**：P1
- **用户价值**：可直接评审和验收筛选规则。
- **需求描述**：原型使用 8 篇 Mock 文章，至少包含有分类、无分类、草稿和已发布文章。
- **验收标准**：
  - [ ] 原型提供 8 篇 Mock 文章。
  - [ ] Mock 数据包含有分类与无分类文章。
  - [ ] Mock 数据包含草稿与已发布文章。
  - [ ] 原型在独立网页与 sandbox iframe 中均无阻断错误（上游已验证）。

# 4. 产品规则

## 4.1 页面与交互

| 位置 / 入口 | 用户操作 | 系统反馈 | 备注 |
|-------------|----------|----------|------|
| 文章列表筛选区 | 切换「仅看未分类」开关 | 立即更新列表；页码回 1；勾选清空；保留关键词与发布状态 | 即时切换，无需确认 |
| 文章列表筛选区 | 开关开启 + 输入关键词/选择发布状态 | 列表取交集 | 与现有 `page.value=1` watch 行为一致 |
| 文章列表空态 | 点击「重置筛选」 | 关闭开关、清空关键词与发布状态、页码回 1、勾选清空 | 仅在有活动筛选时出现 |

## 4.2 字段与校验

| 字段 | 类型 | 是否必填 | 默认值 | 校验规则 | 展示 / 使用位置 |
|------|------|----------|--------|----------|-----------------|
| 仅看未分类（uncategorized，暂定） | boolean | 否 | false | 开/关 | 筛选区开关；影响列表查询 |

> URL query 参数命名与兼容策略为待确认项（OQ-002），最终由技术设计确定。

## 4.3 状态与流转

| 操作 | 前置状态 | 目标状态 | 用户可见反馈 |
|------|----------|----------|--------------|
| 开启开关 | 普通列表 | 仅未分类列表 | 列表刷新为未分类文章 |
| 关闭开关 | 仅未分类列表 | 普通列表 | 列表恢复普通筛选 |
| 切换开关 | 任意 | 页码=1、勾选清空 | 页面回到第一页 |
| 重置筛选 | 空态/有活动筛选 | 默认列表 | 筛选清空、列表恢复 |

## 4.4 接口或数据契约

| 契约对象 | 变化内容 | 是否兼容 | 关联需求 |
|----------|----------|----------|----------|
| Console 内部查询（listPosts） | 需表达「分类为空」语义，与 keyword/labelSelector/fieldSelector/page/sort 组合 | 预期兼容（新增可选过滤，不破坏既有参数） | REQ-002、REQ-003 |
| URL query 参数 | 新增开关对应 query 参数（命名待定） | 新增参数，向后兼容 | REQ-001、REQ-004 |
| 对外 API / SDK / Webhook / CLI | 无变化 | 是 | - |

> Console 内部查询契约、是否复用 `spec.categories` 索引、是否需重新生成 API Client，属于下游技术设计范围（OQ-001、OQ-002）。

# 5. 约束与风险

## 5.1 非功能要求

| 类别 | 要求 | 验收方法 |
|------|------|----------|
| 兼容性 | 不改变现有筛选、分页、勾选和空态行为；新增开关与现有筛选并存 | 回归现有筛选组合 |
| 性能 | 真实实现应复用现有列表查询路径，避免全量扫描；具体方案由技术设计确认 | 技术设计评审 |
| 可访问性 | 开关具备可访问名称与 `aria-checked`；键盘与焦点行为沿用现有组件 | 人工/自动化可访问性检查 |
| 响应式 | 筛选区允许换行，不新增移动端专属布局 | 窄屏验证 |
| 回滚 | 关闭或移除开关不影响现有文章列表功能 | 功能回归 |

## 5.2 风险与待确认

| 类型 | 描述 | 影响 | 处理方式 |
|------|------|------|----------|
| 待确认 | Console 内部查询如何表达「分类为空」（OQ-001） | 影响真实接入、分页准确性、性能 | 下游技术设计确认；仓库已具备 `isNull`/`FieldSelector` 与 `spec.categories` 索引基础 |
| 待确认 | URL query 参数命名与兼容策略（OQ-002） | 影响链接分享、回退与维护 | 下游技术设计确认 |
| 风险 | 开关与「分类」下拉语义互斥 | 用户同时选择可能困惑 | 开启开关时建议禁用或忽略分类下拉（留给技术设计/UX 细化） |
| 风险 | 真实后端未确认前，原型使用 Mock 数据 | 原型行为与真实结果可能不一致 | 集成阶段替换为真实查询并补集成测试 |

# 6. 验收清单

- [ ] 筛选区新增默认关闭的「仅看未分类」开关，即时切换。
- [ ] 开启后仅显示未分类文章，关闭后恢复普通列表。
- [ ] 可与关键词、发布状态组合，取交集。
- [ ] 切换开关时页码回 1、勾选清空、关键词与发布状态保留。
- [ ] 组合筛选无结果时沿用现有空态并提供「重置筛选」。
- [ ] 原型 8 篇 Mock 文章覆盖有分类/无分类/草稿/已发布。
- [ ] 非目标（编辑器、分类管理、权限、主题端等）未被触及。
- [ ] 待确认项（查询契约、URL 参数命名）已标记，不阻塞本 Spec 进入技术设计。
