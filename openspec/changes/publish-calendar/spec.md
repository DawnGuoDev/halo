# 产品 Spec: Halo 管理后台「内容发布日历」

> Spec 用来说明要解决什么问题、为什么要做、做到什么程度。
> 本文件基于上游产品设计 PRD（`artifacts/产品设计/PRD 文档/PRD-内容发布日历.md`）与仓库代码核实，聚焦产品行为约束，供下游技术设计与研发执行使用。实现细节不在本文范围内。

---

# 1. 背景与目标

## 1.1 背景

管理后台「内容」组现有文章、页面、评论、附件四个菜单；文章管理页以「列表 + 筛选 + 分页」呈现，编辑只能在一维列表中寻找未来要发布的文章，对"哪几天扎堆、哪天空着"没有全局感知。发现排期冲突后需逐篇进入文章设置弹窗调整发布时间，路径长且容易改错。

已核实的仓库证据：

| 事实 | 证据 |
| --- | --- |
| 文章列表为列表 + 筛选 + 分页，无按日期组织视图 | `ui/console-src/modules/contents/posts/PostList.vue` |
| 发布时间仅在文章设置弹窗的 `datetime-local` 字段修改 | `PostSettingModal.vue` |
| 定时发布由后端 Reconciler 推导：`spec.publish=true` 且 `publishTime > now` 时打 `scheduling-publish` 标签并 requeue | `application/src/main/java/run/halo/app/core/reconciler/PostReconciler.java#schedulePublishIfNecessary` |
| 列表接口支持 keyword / publishPhase / categoryWithChildren / labelSelector / sort / 分页；**无** publishTime 区间参数 | `application/src/main/java/run/halo/app/content/PostQuery.java` |
| 浏览需 `system:posts:view`；修改需 `system:posts:manage` | `application/src/main/resources/extensions/role-template-post.yaml` |

## 1.2 目标

| 目标 | 衡量方式 | 目标值 / 判断标准 |
| --- | --- | --- |
| 编辑一次进入即可看到某月排期分布 | 月历视图默认展示当前月，上月/下月/回到本月可用 | 进入页面默认当前月，切换月份正确 |
| 不离开页面即可完成发布时间调整 | 详情弹窗内可改时间并保存，保存后月历与列表同步 | 保存后视图即时更新，无需刷新 |
| 减少误操作 | 新时间必须晚于当前时间；已发布文章只读 | 非法时间被拦截并提示；已发布不可编辑 |

## 1.3 不做什么

- 不做拖拽排期、批量改时间、日历订阅（iCal）、周/日视图。
- 不修改文章正文、标题、分类、标签、可见性等非 publishTime 字段。
- 不为页面（SinglePage）提供发布日历，不改动页面模块。
- 不改变后端定时发布机制、标签语义与 Reconciler 行为。
- 不改造文章列表页既有入口与交互（是否在文章列表页加入口见 §5.2 Q3）。
- 不做多站点/多语言排期。

# 2. 用户与场景

| 用户 / 角色 | 使用场景 | 当前痛点 | 期望结果 |
| --- | --- | --- | --- |
| 编辑（`system:posts:view`） | 月初查看本月排期密度 | 只能翻列表，看不出日期分布 | 打开日历即可看到整月分布 |
| 内容运营（`system:posts:manage`） | 发现两篇稿子撞在同一天，需后移一篇 | 逐篇进设置弹窗，来回切换 | 在日历上点开即可改时间 |
| 只读观察者（无 manage 权限） | 查看发布计划 | 无 | 可浏览所有视图，看不到保存动作 |
| 窄屏/移动端编辑 | 外出时查看排期 | 表格横向挤压 | 月历可横向滚动，导航可折叠 |

# 3. 功能需求

## REQ-001: 页面入口与直达

- **优先级**：P0
- **用户价值**：编辑能在「内容」区域稳定找到排期视图。
- **需求描述**：控制台「内容」菜单组新增「发布日历」菜单项，点击进入独立页面；通过 URL 可直达，刷新或分享链接后仍落在该页。
- **规则**：
  - 菜单项 `group: "content"`，放在「文章」之后。
  - 路由采用 `BasicLayout` 子路由（与文章一致，保留控制台外壳）。
  - 深链接需还原视图（月历/列表）、月份、关键词、分类、发布状态。
- **验收标准**：
  - [ ] 具备 `system:posts:view` 的用户可在侧边栏「内容」组看到并进入「发布日历」。
  - [ ] 直接访问 URL 可打开页面并还原视图、月份与筛选条件。
  - [ ] 不具备权限的用户看不到菜单项，直接访问被路由权限拦截。

## REQ-002: 月历视图

- **优先级**：P0
- **用户价值**：一眼看清某月的发布节奏。
- **需求描述**：以周一到周日 7 列网格展示当前月；有 `publishTime` 的文章按日期落入对应格子，格子内展示标题、状态与计划时间（HH:mm）。
- **规则**：
  - 归属日期以浏览器本地时区的 `publishTime` 日期为准。
  - 不属于当前月的相邻日期格子弱化展示（灰色背景）。
  - 今天高亮（描边 + 圆形日号底色）。
  - 单格超过 2 篇时展示前 2 篇 +「还有 N 篇，查看列表」，点击切换到列表视图。
  - 顶部显示「X 年 Y 月」和本月已排期数量。
  - 上月/下月按钮切换月份；「回到本月」回到当前自然月。
  - 加载时保留格子骨架，不出现布局跳动。
- **验收标准**：
  - [ ] 月历展示 6 周 × 7 天共 42 格，表头为周一至周日。
  - [ ] 文章出现在其 `publishTime` 所在日期格，显示标题、状态、时间。
  - [ ] 点击「上月」「下月」「回到本月」后标题月份与网格正确变化。
  - [ ] 同一天多于 2 篇时可跳转到列表查看全部。

## REQ-003: 列表视图

- **优先级**：P0
- **用户价值**：在窄屏或需按时间顺序逐条处理时使用。
- **需求描述**：以表格展示与月历同一筛选结果的文章，按计划发布时间正序；包含标题、状态、分类、计划发布时间、作者、操作。
- **规则**：
  - 有 `publishTime` 的文章进入「已排期」分组，按时间正序。
  - 无 `publishTime` 的草稿进入「未排期草稿」分组，排在最后。
  - 操作列：已发布显示「查看」（带锁图标），待发布/草稿显示「调整时间」。
  - 行与按钮均可打开详情；键盘 Enter 可达。
  - 窄屏表格局部横向滚动，不挤压列内容。
- **验收标准**：
  - [ ] 切换视图不丢失当前筛选与月份。
  - [ ] 列表行按计划发布时间正序排列，未排期分组在末尾且不显示时间。
  - [ ] 已发布行的操作文案为「查看」，待发布行为「调整时间」。

## REQ-004: 筛选（关键词 / 分类 / 发布状态）

- **优先级**：P0
- **用户价值**：在密集排期中快速定位某一类内容。
- **需求描述**：顶部筛选区提供关键词搜索、分类筛选（支持层级，显示各分类文章数）、发布状态筛选；月历与列表同时生效。
- **规则**：
  - 状态口径沿用现有实现：
    - 已发布 = `content.halo.run/published=true`
    - 定时发布 = `content.halo.run/scheduling-publish=true`
    - 草稿 = 二者均不成立
  - 分类筛选使用 `spec.categories`，支持按分类树选择。
  - 关键词匹配文章标题（列表接口实际还匹配 slug 与摘要，沿用即可）。
  - 筛选值必须可清除；筛选、视图、月份进入 URL，刷新或回退后能恢复。
  - 任一筛选变化后回到第 1 页语义（本页无分页，等价于重置滚动）。
  - 刷新按钮保留当前筛选条件重新拉取。
- **验收标准**：
  - [ ] 选择分类后，月历与列表只显示该分类文章，URL 记录分类。
  - [ ] 选择「定时发布」后，列表只剩定时发布文章。
  - [ ] 无匹配结果时显示筛选空态，可一键清除全部筛选并恢复数据。
  - [ ] 刷新按钮执行后保留筛选条件。

## REQ-005: 文章详情与发布时间调整

- **优先级**：P0
- **用户价值**：不离开日历即可修正排期。
- **需求描述**：点击文章（月历卡片、列表行）打开详情弹窗；待发布文章可修改计划发布时间并保存；已发布文章只读。
- **规则**：
  - 弹窗展示：标题、发布状态（含「等待定时发布」标记）、分类、作者、当前计划发布时间。
  - 待发布（定时发布、草稿）且具备 `system:posts:manage`：显示可编辑的 `datetime-local` 输入与「保存发布时间」主按钮。
  - 已发布：输入只读，不显示保存按钮，给出"如需修改请先取消发布"说明。
  - 无 `manage` 权限：所有文章只读，不显示保存按钮。
  - 保存校验：新时间必须严格晚于当前时间。
  - 保存成功：Toast 提示新时间；若月份变化，自动跳到新时间所在月份；月历与列表立即反映新时间，无需刷新。
  - 保存失败：保留用户已填时间，弹窗内提示失败并可重试。
  - 关闭弹窗（X、取消、Esc、点击遮罩）不保存任何修改。
  - 只修改 `spec.publishTime`，不改变发布状态、分类、内容。
- **验收标准**：
  - [ ] 待发布文章可修改时间并保存，成功 Toast 显示新时间。
  - [ ] 保存后月历卡片移动到新日期，列表视图对应行时间同步更新。
  - [ ] 输入早于或等于当前时间时无法保存，字段旁出现错误提示。
  - [ ] 已发布文章输入框只读且无保存按钮。
  - [ ] 无 `manage` 权限时不出现保存按钮。
  - [ ] 按 Esc 关闭弹窗后数据不变。

## REQ-006: 加载 / 空结果 / 失败重试状态

- **优先级**：P0
- **用户价值**：任何网络与数据情况都有明确反馈，不出现白屏。
- **规则**：
  - 加载：月历显示网格骨架，列表显示行骨架；刷新按钮旋转但不阻塞筛选。
  - 空结果分两种：
    - 无筛选条件但本月无排期 →「本月暂无排期」，提供「回到本月」「查看文章列表」。
    - 有筛选条件但无结果 →「没有符合条件的文章」，提供「清除全部筛选」。
  - 失败：展示「加载排期失败」+ 重试按钮；重试保留当前筛选条件。
  - 保存中：主按钮禁用并显示「保存中…」，防止重复提交。
- **验收标准**：
  - [ ] 首次进入能看到加载骨架，随后出现内容或空/失败状态。
  - [ ] 模拟失败时展示失败态，点击重试后恢复内容。
  - [ ] 有筛选无结果时显示筛选空态，且「清除全部筛选」后恢复。
  - [ ] 保存过程中按钮禁用，重复点击不会产生两次保存。

# 4. 产品规则

## 4.1 页面与交互

| 位置 / 入口 | 用户操作 | 系统反馈 | 备注 |
| --- | --- | --- | --- |
| 侧边栏「内容」组 | 点击「发布日历」 | 进入页面，菜单项高亮 | 与文章同一 `BasicLayout` |
| 视图切换（月历/列表） | 点击 Tab / 方向键 | 切换视图，保留筛选与月份 | Tabbar 样式 |
| 月历头部 | 上月 / 下月 / 回到本月 | 月份变化，网格重绘 | 标题显示「X 年 Y 月」 |
| 月历日期格 | 点击文章卡片 | 打开详情弹窗 | 卡片 title 属性含完整信息 |
| 月历日期格 | 点击「还有 N 篇」 | 切到列表视图 | — |
| 筛选区 | 选择/清除筛选 | 月历与列表同步更新，URL 更新 | 筛选可清除 |
| 列表行 | 点击行或行内按钮 | 打开详情弹窗 | Enter 键同效 |
| 详情弹窗 | 修改时间 + 保存 | 校验 → 保存中 → 成功 Toast / 失败提示 | 字段错误在字段旁 |
| 详情弹窗（已发布） | 查看 | 输入只读、无保存 | 明确说明原因 |
| 失败态 | 点击重试 | 按当前筛选重新请求 | 失败态不清空筛选 |
| 窄屏 | 点击左上菜单按钮 | 侧边栏抽屉展开 | 月历局部横向滚动 |

## 4.2 字段与校验

| 字段 | 类型 | 是否必填 | 默认值 | 校验规则 | 展示 / 使用位置 |
| --- | --- | --- | --- | --- | --- |
| plan publish time（`spec.publishTime`） | datetime-local → ISO | 待发布文章修改时必填 | 取文章现有 `publishTime`；无值时留空 | 必须严格晚于当前时间；非法格式拒绝 | 详情弹窗 |
| 关键词 | 文本 | 否 | 空 | trim 后为空视为未筛选 | 筛选区 |
| 分类 | 单选（树） | 否 | 全部 | 只能选择存在的分类 | 筛选区 |
| 发布状态 | 单选 | 否 | 全部 | 枚举：已发布 / 定时发布 / 草稿 | 筛选区 |

## 4.3 状态与流转

| 操作 | 前置状态 | 目标状态 | 用户可见反馈 |
| --- | --- | --- | --- |
| 修改发布时间（定时发布/草稿） | 待发布 | 待发布（新时间） | 卡片移到新日期，Toast 成功 |
| 修改为更早时间 | 待发布 | 不保存 | 字段旁错误「发布时间必须晚于当前时间」 |
| 查看已发布文章 | 已发布 | 不变 | 只读输入 + 说明 |
| 加载失败后重试 | 失败 | 加载 → 成功/失败 | 骨架 → 内容或失败态 |
| 筛选后无结果 | 任意 | 空态（筛选） | 「清除全部筛选」 |

## 4.4 接口或数据契约

| 契约对象 | 变化内容 | 是否兼容 | 关联需求 |
| --- | --- | --- | --- |
| 文章列表接口（`listPosts`） | 复用现有 `keyword` / `labelSelector` / `fieldSelector=spec.categories=` / `sort` 参数；**不新增**必选参数 | 是 | REQ-002, REQ-003, REQ-004 |
| 文章更新接口 | 复用现有更新能力，仅提交 `spec.publishTime`，不得覆盖其他字段 | 是 | REQ-005 |
| 后端 Reconciler | 不修改；保存后由 Reconciler 重新计算 requeue 与 `scheduling-publish` 标签 | 是 | REQ-005 |
| publishTime 区间查询 | 当前**无**该参数；按月取数方案待技术设计（TD-1） | 待定 | REQ-002 |

# 5. 约束与风险

## 5.1 非功能要求

| 类别 | 要求 | 验收方法 |
| --- | --- | --- |
| 兼容性 | 新增模块不修改文章列表、设置弹窗、Reconciler 等既有行为 | 回归测试现有文章管理流程 |
| 性能 | 月度文章数据量较多时首屏不出现长时间白屏；加载骨架先行 | 技术设计确认取数方案（TD-1）后验证 |
| 安全 | 越权写入由接口层拒绝；无 `manage` 权限不显示保存动作 | 权限测试（REQ-005 AC） |
| i18n | 新增菜单项、页面标题、状态词、空态文案均需多语言词条 | `pnpm -C ui typecheck && pnpm -C ui lint` 通过 |
| 可访问性 | 键盘可达：Tab 焦点、Esc 关闭弹窗、Enter 打开/保存 | 键盘测试 |

## 5.2 风险与待确认

| 类型 | 描述 | 影响 | 处理方式 |
| --- | --- | --- | --- |
| 待确认 | Q1：无 `publishTime` 的草稿是否进月历 | 影响月历密度与"待排期"概念 | 推荐默认：只在列表「未排期草稿」分组展示；待业务确认 |
| 待确认 | Q2：入口形态（独立菜单 vs 文章列表 Tab） | 影响路由与菜单结构 | 推荐默认：独立菜单项 + 直达路由；待业务确认 |
| 待确认 | Q3：是否在文章列表页增加「发布日历」按钮 | 影响文章列表页改动范围 | 推荐默认：不加，仅菜单 + 直达；待业务确认 |
| 技术设计 | TD-1：按月份拉取数据（前端分页聚合 vs 后端新增区间查询） | 影响首屏性能与实现复杂度 | 技术设计节点决策 |
| 技术设计 | TD-2：草稿排期保存后是否立即进入定时发布 | 影响用户在草稿上排期的预期结果 | 技术设计节点决策 |
| 技术设计 | TD-3：月历数据聚合（前端聚合 vs 后端聚合接口） | 影响首屏性能与实现复杂度 | 技术设计节点决策 |
| 技术设计 | TD-4：详情弹窗所需字段来源（`ListedPost` 是否含完整 `spec.publishTime`） | 影响一次交互的请求数 | 技术设计节点确认 |
| 风险 | 月度文章多时前端聚合造成多次请求 | 首屏变慢 | TD-1 方案 B 或降低每页数 |
| 风险 | 保存时覆盖他人并发修改 | 数据丢失 | 复用 `usePostUpdateMutate`（读最新版本后仅合并 `spec.publishTime`） |
| 风险 | 时区差异导致日期落格偏差 | 排期看似错位 | 统一浏览器本地时区展示、ISO 提交，与设置弹窗一致 |
